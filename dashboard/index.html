Judge brief — read this first

  1. Working radar. The board below covers all 40 watchlist protocols (badge W) plus 138 early pre-token rows; every row states an implied value and a farm plan. The code that built it is lib/model.ts, function buildRadar().
  2. Value model. impliedValue() prices each protocol from the snapshot alone: TVL × 0.30, times growth, tenure and chain factors. No name is special-cased. Protocols whose token already trades are set aside in the Live section, at their market cap.
  3. Farm plans. farmSteps() writes five steps per protocol, each with a cost and a time. Click any row to read its plan.
  4. The page. Sort by rank, value, TVL or growth; filter by text, category or watchlist; click any row for its detail view.
  5. Looks made. One palette, one spacing scale, one type stack. No framework, no network.

The model — sakmad-radar-1

implied = max(1, round(TVL × 0.30 × growthMul × tenureMul × chainMul))

growthMul
clamp(1 + change_7d / 100, 0.5, 2.0); change_7d clamped to −50…+100, missing counts as 0
tenureMul
0.5 + min(age_days, 1460) / 1460 × 0.5; age from listed_at to the snapshot date, missing counts as 180 days
chainMul
1 + min(chains − 1, 4) × 0.05

“Records no token” means the snapshot carries no market cap, CoinGecko id or symbol for it — never a claim that it has none. A launch is priced, not predicted: the board says what a token would be worth if the record stayed as it is, not whether or when one comes.
